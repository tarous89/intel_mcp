# Manage research projects

Read [answer standard](../../references/presentation-standard.md) and [access rules](../../references/access-and-evidence.md).

- Use list_projects to locate canonical projects and read_project for analytical reads. Omit kind/controls to read the latest saved view. Explicit controls are read-only overrides; {} means unfiltered. Honor ownership. Use open_project only to present a requested table, page or record view, once ready; do not open it to collect data for analysis.
- Read cached previews with read_project_preview, never re-search or recompute on tab changes. For analytical reads choose limit 1–100 on paid access (prefer 100 for broad counting), follow next_offset, and keep the free first-ten boundary. Workspace display pagination is separate from analytical read size. Read through MCP rather than navigating visible table pages. Use publish_research_workspace for final new results and save_project with expected_revision for project revisions. Use prepare_research_workspace for exploration that is not saved to an account project. Storage calls already retry transient failures up to twice; after automatic_retry_complete=true, leave manual recovery available instead of starting another automatic retry loop. On a user-requested retry, use the returned recovery arguments: save_project for connected publication or project revisions (retain project_id/expected_revision), recover_research_preview for temporary-only storage. Do not blindly repeat guest publication: it creates a separate private preview.
- The extension Connect action requests OAuth and saves the exact retained preview with save_project; its server attaches existing Custom views. If the user chooses “Continue connection in ChatGPT”, use that preview's retained draft with save_project and present the returned workspace. Honor host consent; cancellation leaves the preview available. Website-only import remains a fallback and does not establish MCP OAuth. Preview IDs identify context; cache tokens remain tool arguments, never chat text.
- Successful publish_research_workspace already saves the connected account project. Use save_project for user-requested failed-save recovery with the retained draft, or for an authorized cohort revision with project_id and expected_revision. On REVISION_CONFLICT, read the latest project with read_project and reconcile before revising; retrying unchanged stale arguments cannot resolve it. Save presentation changes with save_project_view using the returned view.version and revision; this does not change cohort membership.
- Preserve the previous ready dataset while a revision prepares. Successful publish_research_workspace and save_project_custom_view already present their results; do not follow either with a redundant open call. Do not claim saved before success. Let the extension show its single-sentence manual-save notice after failed automatic recovery; quote seven-day availability only for confirmed temporary storage, never for a failed cache write or an unsaved Custom view. Do not add duplicate routine expiry footnotes in chat; a connected free account may save without buying access.
