# Custom view procedure

1. Call prepare_project_report for the current project or preview. Keep dataset_id, revision and access_scope. For previews use report_preview exactly (preview_id, snapshot_key, cache_token). Set include_template=true when the rendering reference/template is needed; evidence-only preparation stays concise.
2. For an existing view, recover its content, report_id and expected_version with list_project_reports/open_project_report. Revisions update that view; an explicitly requested copy creates another.
3. Use authorized table data, user-provided content, or registered trial/document evidence. Retrieve profiles/documents with the evidence skill where needed. Keep source_ids and follow all document parts for complete retrieval.
4. Call save_project_report with title, original query, summary (empty allowed), html, dataset_id, revision, source_ids and request_key. Set artifact_kind for the output and evidence_basis for its actual source: trial_evidence requires registered sources; project_tables/user_provided allow an empty list. Set renderer=static for semantic HTML and renderer=interactive for controls or scripts.
5. Revisions pass report_id and expected_version and a fresh request_key. Identical retries retain the original key and payload. REPORT_VERSION_CHANGED requires reading the latest view and reconciling the requested edit. A changed project context requires fresh prepare_project_report and evidence reconciliation. Recovery details identify whether the retained save is retryable or needs correction.
6. The save result opens Custom views. report_saved=true means read-back verified storage. Guest storage is temporary; account connection attaches the project and views. On failure, the retained draft and one recovery control appear in Custom views. Use retry_project_report with retry_id for the retained payload; retention lasts up to 30 minutes in this server session. If it expired, reuse the original content.

## Static renderer
Use semantic HTML and the shell’s supported classes: main/section, h1–h3, p, figure/figcaption, .table-scroll, .bar-chart, .bar-row, .bar-label, .bar-track and .bar-value. Bar tracks use SVG rectangles with viewBox="0 0 100 12" and preserveAspectRatio="none"; labels stay in HTML at a stable size. Other SVG charts use a viewBox sized for their intended display width. Use SVG fill/stroke attributes for marks and matching legend swatches. Keep a legend inside the same SVG or use labeled HTML bar rows. The server provides CSS; custom CSS/scripts require the interactive renderer. Keep HTML below 800 KB.

## Interactive renderer
Use self-contained inline CSS/JS and addEventListener. The opaque-origin sandbox blocks external assets/network, parent DOM/account access and direct database writes. Use task-appropriate non-patient data.

Existing state bridge: window.TrialAgents.getState() reads saved state; setState(object) updates a local draft. A deliberate host Save changes action persists that draft with ownership/version checks. Stable input/select/textarea IDs or names are tracked in state.form. Custom controls initialize from getState() and call setState on edits; keep JSON under 200 KB. Automatic input saving is not provided. Keep this existing mechanism compatible; ordinary generated tracker content can also be revised through ChatGPT.
